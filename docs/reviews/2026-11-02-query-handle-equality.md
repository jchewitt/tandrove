# PERF-01 query-handle equality review

Independent reviewer: `/root/equality_review`, November 2, 2026. The primary agent implemented the focused change, five public regressions, benchmarks and documentation. The reviewer separately examined the implementation, executed targeted/differential checks and verified measurement provenance. No commit preceded independent review.

Scope: reuse the store view's canonical projection string inside acquisition handles instead of copying/serializing the whole snapshot again. A private weak lookup connects the existing frozen facade to its view; that same view was already retained by the facade's bound method closures. Historical snapshots are not lookup keys. A package-internal read-only helper supplies the string without changing public view types or package exports. Handles compare projection, fetching and canonicalized owner error, retaining separate observed/notified comparisons containing only strings/booleans. Store projection/equality and validation behavior remain unchanged. A core patch Changeset joins the batched release.

The review identified untyped custom `Error.message` values as an edge case: raw reference equality would bypass the previous canonical validation. The candidate canonicalizes only the small error component, retaining validation/equality without serializing cached data. Five public regressions cover reentrant stale-to-fresh cycles with early/unread peers, payload names resembling metadata, valid/invalid untyped error messages, owner isolation and listener failure/unsubscription during reentrant publication. Existing regression coverage retains loading, partial/null/error states, disposal and value-equal A → B → A behavior.

The reviewer approved the final runtime/tests without actionable findings and independently passed **60 targeted tests**. Their diagnostic compared previous/candidate handles through real current store facades (store behavioral logic is unchanged): **1,200 deterministic 50-action traces, 60,000 actions and 391,164 matching observations**. It covers snapshots, outer-reference changes, callbacks, failures, early peer reads, reentrant commits/fetching, disposal, listener removal/errors and typed/untyped error components. This is evidence for tested histories rather than a proof for every possible execution.

The primary agent passed `pnpm check`: formatting, builds, generated schema checks, strict source/type checks, **442 tests** and isolated real-tarball ESM/TypeScript/Angular APF/AOT consumers. `pnpm test:browser` passed **25 Chromium scenarios**. Hosted CI and merge evidence belong to the feature PR; timing thresholds are not part of the correctness suite.

Only `acquisition.ts` and `state-store.ts` differ in core/GraphQL runtime source. Both runs used the unchanged harness without concurrent deliberate builds, tests or probes.

The reviewer independently verified baseline bytes against HEAD, candidate bytes, parent/dirty provenance, all three harness hashes, versions, environment and sampling. They checked the candidate browser bundle hash and reconstructed the baseline bundle by substituting the two prior modules, matching its recorded hash exactly. All **264 statistic groups** (132 per report), heap ranges, lifecycle counters and 21 verified reacquisitions per browser profile were checked. Weak keys do not establish that engine capacity immediately returns or that all lifecycles are bounded. B7c.3 still requires allocation attribution, longer-session assessment and intended-device/application budgets.

Subtrees overlap and include startup, fixtures and assertions, so these are attribution clues rather than additive operation timings. [Performance documentation](../PERFORMANCE.md#november-2-query-handle-equality-reuse) preserves these limits.
