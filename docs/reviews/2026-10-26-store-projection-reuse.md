# PERF-01 store projection reuse review

Independent reviewer: `/root/projection_review`, October 26, 2026. The primary agent implemented the store optimization, collected the unchanged benchmark and updated documentation. A separate agent, `/root/projection_tests`, implemented seven public store regressions. No commit preceded independent review.

Scope: prepare canonical cell keys and immutable response paths once per view selection, then reuse those descriptors across records and updates. Request bookkeeping reuses the existing immutable data/status projection and compares fetching separately. Data commits still reproject and use canonical value equality. All views update before callbacks, including the existing direct-store reentrant behavior. Public APIs, operation planning, transactional commit cloning and request-version semantics remain unchanged. Inner record/path reference identity is not a new public contract. A core patch Changeset joins the batched release.

The reviewer approved the runtime, tests and documentation without actionable findings. They independently replayed 600 deterministic 65-action traces against the previous store: **39,000 generated actions and 74,641 matching observations**, covering snapshots, outer reference changes, callbacks, failures/atomicity, reentrant commits/fetching/disposal and frozen wrappers. This is equivalence evidence rather than a proof for every history. They also passed **47 targeted store/projection/snapshot/concurrency tests**. The seven new public regressions cover loading-only/value-equal updates, request replacement and canonical argument/alias coverage, nested missing/null/error states, failed-batch atomicity, unknown/empty/null resources, reentrancy and captured selection immutability.

The primary agent passed `pnpm check`: formatting, builds, generated schema checks, strict source/type checks, **429 tests** and isolated real-tarball ESM/TypeScript/Angular APF/AOT consumers. `pnpm test:browser` passed **25 Chromium tests**. Hosted CI and merge evidence belong to the feature PR. Timing thresholds are not part of the correctness suite.

The unchanged `pnpm measure:readiness` harness passed all Node dimensions, Chromium 1×/4× profiles and lifecycle assertions without concurrent deliberate builds, tests or probes. The [raw report](../measurements/b7-store-projection.json) records parent `3b08ab49d2790ed1b83c9ee885424e82bf529a76`, `sourceDirty: true` and runtime digest `843be1dc9bfa34e157c80a3758a2fdb70698858c6f5e78ea25a12cff2e4815a0` for the measured candidate. Only `state-store.ts` differs in core/GraphQL runtime source from that parent.

Against the handle snapshot run, 5,000-record Node full/narrow medians fell from 2,305.91/1,575.38 ms to 1,430.54/663.32 ms. Unthrottled 1,000-record Chromium medians fell from 291.50/191.10 ms to 164.90/68.90 ms. All 14 recorded refresh medians improved in this bounded workload. Active whole-isolate post-GC heap was about 24.15–24.18 MB versus the prior roughly 28.84 MB; released batches had zero harness-owned handles/subscriptions and in-flight fixture calls, with 21 verified reacquisitions per profile. These observations are not general speedup guarantees, isolated allocation accounting or proof of long-session memory safety.

The reviewer independently verified the runtime digest, three harness hashes, browser bundle hash, revision/dirty provenance, environment and package versions. They recomputed all **132 statistic groups** and checked the timing/heap tables and percentages. The separate Node attribution profile puts `View.update` at 321.06 sampled inclusive ms (15.82%), down from 1,912.48 ms (51.22%). `canonicalInput` still accounts for 1,201.53 ms (59.21%) across multiple callers. These overlapping process-wide samples include startup, fixtures and assertions; they identify remaining canonical copying/serialization work rather than precise operation timings. [Performance documentation](../PERFORMANCE.md#october-26-store-projection-reuse) preserves the evidence and limitations.

**PERF-01 remains open.** This completes B7c.2c; B7c.2d will investigate redundant canonical copying/serialization while preserving validation, canonical identity and exact equality. Externally frozen containers alone do not establish validated, deeply immutable inputs. B7b–B7d and AX2–AX4 remain open pending the real application trial, intended-device evidence, justified responsiveness/memory budgets and readiness review. Publication remains batched; this feature does not authorize merging the release PR.
