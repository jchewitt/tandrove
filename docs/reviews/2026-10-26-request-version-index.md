# PERF-01 request-version index review

Independent reviewer: `/root/version_index_review`, October 26, 2026. The primary agent implemented the runtime index, collected measurements and updated the plan. A separate agent, `/root/version_index_tests`, implemented eight public-behavior regressions. No commit preceded independent review.

Scope: index committed field-version stamps by canonical record identity and path; skip structural scans only when a conservative maximum proves no newer stamp can exist. Keep resource-wide retry/deduplication and root-replacement checks, request intents, mark-only invalidations, object-context markers, record-local structural barriers and disposal/reset semantics. The maximum uses `Math.max` because an older disjoint response may commit later. No public API, source adapter, authoritative server-version contract or snapshot implementation changes. A core patch Changeset joins the fixed, batched release group.

The reviewer approved the runtime and eight regressions without actionable findings. They independently passed 38 concurrency/ingest/version-index tests and a deterministic differential probe against the previous implementation: 140,957 observations across 60 histories and 15,000 operations, including adversarial out-of-order commits, canonical identities/arguments, context markers, invalidations, root resets and disposal. This supports equivalence for the exercised cases, not a proof over every possible history. Regression tests cover externally visible behavior without timing thresholds or private-map assertions.

The primary agent passed `pnpm check`: formatting, package builds, generated schema checks, strict source/type checks, **415 tests** and isolated real-tarball ESM/TypeScript/Angular APF/AOT consumers. `pnpm test:browser` passed **25 Chromium tests**. The independent reviewer checked whitespace and the complete code/test/documentation candidate before commit. Hosted CI and merge evidence belong to the feature PR.

The unchanged `pnpm measure:readiness` harness passed all Node dimensions, Chromium 1×/4× profiles and lifecycle assertions. The [full report](../measurements/b7-version-index.json) preserves the measured dirty candidate and runtime/harness/bundle provenance. The 5,000-record Node full median fell from 15,936.23 to 2,716.69 ms; unthrottled 1,000-record Chromium full refresh fell from 716.90 to 334.60 ms. The separate-session 4×/1,000-record narrow median was slower, 1,267.40 to 1,397.30 ms, and remains disclosed.

A separate [ABBA diagnostic](../measurements/b7-version-index-ab.json) substituted only the previous request-version module and ran old/indexed/indexed/old in fresh 4× contexts. Both indexed runs improved full and narrow medians against both old runs in that session. The [exact measured script](../measurements/b7-version-index-ab-script.txt) is archived without reformatting. The reviewer verified its hash, the candidate source hash, the matching candidate/formal bundle hash, unchanged harness/environment, and the per-run statistics. The diagnostic supports this optimization under the measured conditions; it neither explains all cross-session variation nor replaces the formal results. [Performance documentation](../PERFORMANCE.md) retains both reports and their limits.
